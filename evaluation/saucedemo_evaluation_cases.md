# SauceDemo 网站 Agent 评测用例

> 评测目标网站：https://www.saucedemo.com/
>
> 评测对象：本项目 WebAgent（三 Agent 架构 / 单 Agent 架构）
>
> 说明：SauceDemo 是 Sauce Labs 提供的公开测试电商网站，包含完整的登录、商品浏览、购物车、结账流程。以下 10 个用例覆盖从简单到复杂的各类网页自动化场景，用于评测 Agent 的规划、执行、验证与异常处理能力。

---

## 测试账号信息

| 账号 | 密码 | 说明 |
|------|------|------|
| `standard_user` | `secret_sauce` | 标准用户，可正常完成所有流程 |
| `locked_out_user` | `secret_sauce` | 锁定用户，登录时显示错误信息 |
| `problem_user` | `secret_sauce` | 问题用户，部分操作行为异常 |
| `performance_glitch_user` | `secret_sauce` | 性能问题用户，页面加载缓慢 |

## 用例 1：成功登录

- **难度**：简单
- **目标**：验证 Agent 能完成基本登录流程
- **任务描述**：
  > 打开 https://www.saucedemo.com/ ，使用用户名 standard_user 和密码 secret_sauce 登录，登录成功后告诉我页面上显示的商品数量。
- **预期结果**：
  - 成功登录并跳转到商品列表页（inventory.html）
  - 正确报告商品数量为 6
- **评测点**：
  - 能否正确打开页面
  - 能否定位并填写用户名/密码输入框
  - 能否点击登录按钮
  - 能否验证登录成功并提取商品数量

## 用例 2：登录失败（错误密码）

- **难度**：简单
- **目标**：验证 Agent 能处理登录失败场景并正确报告错误
- **任务描述**：
  > 打开 https://www.saucedemo.com/ ，使用用户名 standard_user 和密码 wrong_password 尝试登录，告诉我登录是否成功，如果失败请告诉我页面显示的错误信息。
- **预期结果**：
  - 登录失败，停留在登录页
  - 正确提取并报告错误信息（"Username and password do not match any user in this service"）
- **评测点**：
  - 能否识别登录失败
  - 能否提取页面上的错误提示文本
  - 能否如实报告失败而非编造成功

  - 能否正确处理登录失败
  - 能否提取特定错误信息
  - 能否如实报告失败

## 用例 4：商品排序（价格从低到高）

- **难度**：中等
- **目标**：验证 Agent 能操作下拉框并验证排序结果
- **任务描述**：
  > 打开 https://www.saucedemo.com/ ，使用 standard_user 登录后，将商品列表按价格从低到高排序，然后告诉我价格最低的商品名称和价格。
- **预期结果**：
  - 成功登录
  - 通过下拉框选择 "Price (low to high)"
  - 正确识别价格最低的商品（Sauce Labs Onesie，$7.99）
- **评测点**：
  - 能否操作下拉框（browser_select）
  - 能否验证排序是否生效
  - 能否提取排序后的商品信息

## 用例 6：完整购物流程（结账）

- **难度**：困难
- **目标**：验证 Agent 能完成从登录到结账的完整电商流程
- **任务描述**：
  > 打开 https://www.saucedemo.com/ 使用 standard_user 登录，将 "Sauce Labs Backpack" 加入购物车，进入购物车，点击 Checkout，填写结账信息（名字 John，姓氏 Doe，邮编 12345），继续到总览页面，告诉我总价是多少，然后完成订单。
- **预期结果**：
  - 完成登录 → 添加商品 → 购物车 → 结账信息 → 总览 → 完成订单
  - 正确报告总价（$29.99）
  - 最终显示 "Thank you for your order!" 成功页面
- **评测点**：
  - 多步骤任务规划能力（Planner）
  - 表单填写能力
  - 多页面导航能力
  - 最终结果验证能力（Verifier）

## 评测评分标准

| 评分项 | 说明 | 权重 |
|--------|------|------|
| 任务完成度 | 是否成功完成目标任务 | 40% |
| 步骤正确性 | 执行步骤是否合理、无多余操作 | 20% |
| 异常处理 | 遇到错误/异常时能否正确处理 | 20% |
| 结果准确性 | 提取的信息是否准确 | 20% |

## 评测执行建议

1. 每个用例独立运行，使用 `browser_clear_state` 清除浏览器状态，避免登录态干扰
2. 记录每个用例的 trace（`web_traces/multi_agent_trace.jsonl`）用于分析
3. 对每个用例记录：是否成功、耗时、LLM 调用次数、错误处理情况
4. 建议先运行简单用例（1-3），再运行中等用例（4-5、7-10），最后运行复杂用例（6）
